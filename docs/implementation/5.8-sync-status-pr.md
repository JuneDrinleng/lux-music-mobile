## 预览差异与运行时边界（全部）

- 允许的差异：PrimaryButton / SecondaryButton / BackButton 复用 compact 版本，按钮可见高度约 28、hitSlop 后约 44；其余样式按预览。返回钮放在原 40 高的布局槽内。
- 没有自动重试排程时（认证 / HTTP 探测失败、终止的 socket 错误），不会伪造「下次 N 秒后」：16A meta 使用「已尝试 N 次 · 点按重试」，16D 使用「点按查看 · 重试连接」。只有现有 socket 自动退避确实排程时，才显示预览的秒数。初次认证失败计为本次连接尝试 1 次，socket 数量使用原有 failedNum。
- 16D 只示意顶部状态区域；实现保留既有设置搜索图标、Dock 以及后续完整设置内容。根页搜索图标仍位于返回行右侧，预览未画出该图标。
- 真正无法取得版本值时显示「未知」，不填入预览的 1.9.0 / 2.1。旧 `/hello` 错误提供的是协议 vN，按真实协议号呈现。`server-info.minClientVersion` 是客户端最低版本约束；兼容性使用原 `versionAtLeast` 判定，展示沿用本次明确指定的 16B / 16D「服务器 X < 需要 Y」及正文模板，不能将它当成服务器最低版本元数据。
- 静态预览的 16A–16D 标号、固定时间 / 信号和「四种状态示意」说明属于设计标注；运行界面用系统状态栏且只显示当前一行。
- 原生字体 / emoji 字形及最终设备截图尚未验证；未声称像素级截图验收通过。

## 状态和重连行为

- `src/utils/syncStatus.ts` 是纯映射模块，含有顺序明确的错误映射表、状态路由、host / 版本文字数据、既有退避公式及 deadline → 秒数转换。401 / 已知失效 code 优先于网络错误；403 本身不当作失效；LX 授权码错误保留原授权码流程。
- 原 socket `heartbeatTools` 仍是唯一自动重连定时器。公式仍为 `min(2000 + floor(failedNum / 2) * 3000, 30000)`；状态只公开 attempts / retryAt。1 秒 UI 时钟只刷新显示，不建立重试循环；离开设置即停止刷新。
- 立即重连复用当前 socket 的 URL / key，取消已有连接 / 心跳 / 重试定时器；没有 socket 时调用原 connectLuxServer / connectServer。
- 「先离线使用」仅返回首页：已有 socket 重试继续；原来没有自动排程的认证失败仍等待手动重试。不会隐式停用同步或切换数据空间。
- disabled、显式断开及本地无 host 状态不显示状态区；失效账号即使被现有流程停用同步，也保留失效行。本地用户切换会清空当前 host 并移除该行。
- 修复 `/hello` 原本吞掉版本错误的问题；Lux 认证读取同一个 `/api/server-info` 并使用 serverCheck 的解析 / 版本比较，旧端点缺失或格式不支持时继续原认证流程。
